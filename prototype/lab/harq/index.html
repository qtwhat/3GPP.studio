A failed block is not thrown away.
It is half of the next attempt.

Radio corrupts data all the time, and the network plans for it. The receiver keeps every damaged copy, asks for another, and decodes the two together. Meanwhile the sender does not wait: it keeps several blocks in the air at once. You are the noise. Jam a slot and watch what it costs.

The whole story, from zero

  1. Every block carries a checksum

    Data crosses the air in transport blocks, one per slot. Each has a checksum, so the receiver knows at once whether it decoded the block correctly.

  2. The receiver answers with one bit

    A few slots later it reports ACK, got it, or NACK, did not. That gap is the round trip: time to decode, plus time for the answer to travel back.

  3. A damaged copy is kept

    The receiver stores the failed attempt in a soft buffer. The retransmission carries the same data protected in a different way, called a redundancy version. Decoded together, two weak copies often succeed where neither would alone. This is the hybrid in hybrid ARQ.

  4. One process sends, then waits

    A HARQ process handles one block at a time. After sending, it cannot be reused until the answer comes back. With a single process, most slots would sit empty.

  5. So several take turns

    The sender runs several processes side by side, and each grant names the process it belongs to. While one waits for its answer, the others fill the slots. Enough processes to cover the round trip means no slot is wasted.

  6. One flag tells new from repeat

    Each grant carries a new-data indicator. If it has flipped since that process was last used, the block is new and the soft buffer is cleared. If it has not, the block is a retransmission and is combined with what is stored.

Blocks therefore finish out of order, and the layer above (RLC) puts them back in sequence. If HARQ gives up on a block, RLC notices the gap and can ask for the data again. In the uplink the base station sends no ACK at all: it simply grants a retransmission or grants new data, and the indicator says which.

What each number is for

Some of these are configured by RRC, and some are simply choices the base station's scheduler makes.

What this lab simplifies. One direction, one cell, one block per slot, always more data to send. Signal quality is three made-up levels: a clean transmission carries all that decoding needs, a weak one 60%, a jammed one 30%, and with combining the copies simply add. Real combining gain depends on the code, the redundancy versions and the channel. The answer for a block arrives a fixed number of slots after it was sent, and the process can be reused in that same slot. Retransmissions go before new data. A dropped block is skipped by the in-order row as soon as the sender gives up. Not modelled: feedback errors, code block groups, bundled or multiplexed ACKs, HARQ with feedback disabled, the DRX timers that keep a phone awake for retransmissions, and RLC retransmission.

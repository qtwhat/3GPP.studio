cellsTriggeredList: who is in the list, and who is in the report

With event A3, the UE keeps a list of the neighbour cells that triggered the event. A cell enters the list after it has been above the entry line for a full timeToTrigger and leaves after a full timeToTrigger below the leave line. Each MeasurementReport carries only the strongest listed cells, up to maxReportCells. Draw the two neighbours' levels below and watch the list, the report count and each report.

When a cell enters or leaves the list

A cell enters above Mp + Off + Hys and leaves below Mp + Off − Hys, each only after the condition has held for a full timeToTrigger. Watch panels 1 to 3.

What one report carries

maxReportCells

The most neighbour cells one report can carry, strongest first. A listed cell that does not fit is left out of that report but stays in the list. In panel 4 this is the number of slots in each report box.

How many reports are sent

reportOnLeave

reportAmount is not a cell count. Periodic reports stop once this many have been sent since the count was last reset (the dashed line in panel 5). A newly listed cell resets the count to 0, and if reportOnLeave is true a report is still sent when a cell leaves.

    What to take away

    The list changes only after a full timeToTrigger. With Off = 3 dB and Hys = 1 dB, a neighbour enters above −86 dBm (Mp + Off + Hys) and leaves below −88 dBm (Mp + Off − Hys). Both inequalities are strict. Between −88 and −86 dBm nothing happens: a cell in the list stays in it, and a cell outside stays outside. A short dip below the leave line that ends before timeToTrigger cancels the pending leave.

    Each new cell restarts the report count, and leaving does not. In the walkthrough, A enters at 360 ms (report 1). B enters at 560 ms, which resets numberOfReportsSent to 0 and sends report 2 at once. The periodical timer that was due at 600 ms is stopped and restarted, so the next report comes at 800 ms. After that the count is 2 = reportAmount, so periodic reports stop. A and B are still in the list.

    reportAmount and maxReportCells count different things. maxReportCells is how many cells fit in one report (panel 4: the size of each report box). reportAmount is how many reports go out before periodic reporting stops (panel 5: the dashed line). It is not a lifetime limit: a newly listed cell resets the count to 0, and with reportOnLeave a report is still sent when a cell leaves, even above reportAmount. In the walkthrough with maxReportCells = 2, the report at 800 ms carries B and A; with maxReportCells = 1 it carries only B. Either way it is the second report since B was added, so periodic reporting stops there.

    Being listed is not the same as being reported. With maxReportCells = 1, the report at 560 ms carries only B (−83 dBm). A (−84 dBm) is still in cellsTriggeredList and is simply not the strongest. Set maxReportCells to 2 and both appear, strongest first.

    Leaving, with reportOnLeave = true. When A leaves at 1000 ms, a report is sent with the cells still listed, so it carries B, and the count goes to 3, above reportAmount. The report does not name A as the cell that left; that needs enteringLeavingReport, which this page leaves out. When B leaves at 1360 ms the list is empty: a report is still sent, with the serving cell result and no neighbour cells, then the reporting entry for this measId is deleted. When A returns at 1760 ms it is a first cell again and the count starts from 0.

    Model scope and limits

    One measId with event A3, reportType eventTriggered, RSRP as the trigger and sorting quantity, and no numberOfTriggeringCells. Inputs are already layer 3 filtered and arrive every 40 ms with none missing. The SpCell is fixed at −90 dBm. offsetMO and cellIndividualOffset are zero for all cells. Off and Hys are limited to small ranges that fit the chart, and only a subset of the timeToTrigger, reportInterval and reportAmount values is offered.

    Teaching conventions. timeToTrigger counts from the first qualifying sample: the cell is added (or removed) on the first sample where the condition has held on every sample since then and at least timeToTrigger has passed. The page offers only timeToTrigger values that are multiples of the 40 ms sample period (ms0, 40, 80, 160, 320, 480, 640), so each change happens exactly timeToTrigger after the first qualifying sample. When a periodical timer expiry falls on a sample instant, the page handles the expiry first. On one sample, entries are handled before leaves, following the order of the §5.5.4.1 text. When two listed cells have equal RSRP, the page lists A first. The specification gives no order for these ties.

    Not modelled. numberOfTriggeringCells, enteringLeavingReport and cellsMetLeavingCond, reportOnBestCellChange, useT312, other events, several measIds, measurement gaps and missing samples, beam-level results, and the mapping of RSRP to the reported RSRP-Range index. Reports here show dBm.

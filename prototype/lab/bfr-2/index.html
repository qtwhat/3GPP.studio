One bad reading is a blip.
Three close together is a failure.

At high frequencies a phone talks to the base station through one narrow beam, and a hand or a passing bus can cut it in milliseconds. The phone must tell a blip from a real loss, then find another beam by itself. Be the obstacle: block the beam and watch it decide.

What just happened

    Four things to try

    1. Tap once. One bad reading is counted, and after enough quiet readings the counter forgets it.
    2. Play Flicker. Then set the timer to pbfd3 and play it again. Same bad readings, opposite verdict.
    3. Set the max count to n1 and tap. Every blip now costs a full recovery.
    4. Set the threshold to −82 dBm and play Wall. No beam qualifies, so the phone falls back to the slow shared procedure.

    The whole story, from zero

    1. The link is one beam

      At millimetre-wave frequencies the base station (gNB) aims a narrow beam at the phone. The beam in use is the serving beam. Others exist, often bouncing off walls, and are usually weaker.

    2. The phone keeps checking it

      Every few milliseconds the physical layer asks one question about the serving beam: could I still decode a control message on this? If the answer is no, it sends one beam failure instance up to MAC.

    3. MAC counts, and forgets

      Each instance adds 1 to BFI_COUNTER and restarts a timer. If the timer runs out with no new instance, the counter goes back to 0. A good reading never clears the counter; only time does.

    4. Enough of them is a beam failure

      When the counter reaches beamFailureInstanceMaxCount, MAC declares beam failure. Nothing has been fixed yet. This only starts the recovery.

    5. The phone picks a new beam and knocks

      It looks for a candidate beam stronger than rsrp-ThresholdSSB and sends a random access preamble reserved for that beam. Which preamble arrives tells the gNB which beam the phone chose.

    6. The gNB answers on the new beam

      A control message for this phone, on a search space reserved for recovery, completes it. The counter resets and the link continues on the new beam, in the same cell. If no attempt ever succeeds, the heavier radio link failure handling takes over.

    What each number is for

    The gNB picks these per phone and sends them by RRC. Together they set how jumpy detection is and how picky recovery is.

    How many bad readings before acting?
    beamFailureInstanceMaxCount
    n1 to n6, n8, n10
    Low reacts fast but treats blips as failures, and each one costs a random access. High rides out blips but leaves the phone longer on a dead beam.
    How long does one bad reading stay on the record?
    beamFailureDetectionTimer
    pbfd1 to pbfd6, pbfd8, pbfd10, counted in reporting periods
    Short forgets quickly, so scattered bad readings never add up. Long lets a flickering beam accumulate into a failure.
    How good must a replacement beam be?
    rsrp-ThresholdSSB
    with a list of candidate beams and their reserved preambles
    Low accepts almost any beam and risks landing on a poor one. High may leave no candidate, and the phone must use contention-based random access instead.
    How long may the reserved preambles be used?
    beamFailureRecoveryTimer
    10 to 200 ms, optional
    While it runs the phone may use its reserved, collision-free preambles. After it expires those are off limits. Not modelled in this lab.

    What this lab simplifies. One cell, one set of detection reference signals, no DRX. A blocked beam is simply bad and an unblocked one good; there is no real radio channel. The reporting period is an illustrative 20 ms and the animation runs about 12 times slower than real time. Recovery takes a fixed 60 ms with a reserved preamble and 120 ms with the contention-based fallback; real timings depend on configuration, and retries, power ramping, back-off and beamFailureRecoveryTimer are not modelled. The phone here picks the strongest qualifying beam; the specification allows any qualifying one. When a bad reading lands exactly as the timer would expire, the reading is counted first, so pbfdN tolerates N−1 quiet periods; the specification does not order those two events. SCell recovery (a MAC CE instead of random access) and two-TRP operation are out of scope.
